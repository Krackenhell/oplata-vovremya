# Пилот, внедрение, защита данных

## Путь к пилоту в ВТБ

| Этап | Срок | Что делаем | Критерий перехода |
|---|---|---|---|
| 0. Валидация (сейчас) | до 15.11 | 10 интервью, разбор 50 реальных просроченных счетов респондентов (обезличенно) | H1, H2 не опровергнуты |
| 1. Закрытый пилот вне банка | 2–4 недели | 10–20 компаний МСБ: загрузка реестра и выписки, пересылка писем клиентов; разметка причин бухгалтером | macro-F1 ≥ 0,75, принятые рекомендации ≥ 60% |
| 2. Песочница банка | 1–2 месяца | развёртывание в тестовом контуре ВТБ: выписка через внутренний API, Jev и LLM on-prem, 100–300 клиентов, A/B по контрагентам | +8 п.п. к оплатам «к сроку + 7», ошибки сверки ≤ 1% |
| 3. Масштаб | далее | функция в интернет-банке для МСБ, воронка в ВТБ Факторинг, экран клиентского менеджера | конверсия в факторинг ≥ 3% активных |

Стоп-критерии пилота: ошибка автосверки > 3%; более 5% писем с фактическими ошибками после валидатора;
жалобы клиентов-плательщиков на тон писем; отсутствие эффекта на сроке оплаты после 2 месяцев.

Что нужно от банка: тестовый контур, выписки клиентов-участников (по согласию), контакт продуктовой команды МСБ
и ВТБ Факторинга, требования ИБ к размещению моделей.

## Архитектура внедрения

```
Интернет-банк МСБ ──► Оплата вовремя (контур банка)
                       ├─ выписка, платежи (внутренний API банка)
                       ├─ реестр счетов (1С / CSV / выставленные в банке)
                       ├─ статусы документов (Диадок / СБИС API, МЧД)
                       ├─ переписка (пересылка писем, IMAP по согласию)
                       ├─ Jev on-prem — причины и признаки (вероятности)
                       ├─ LLM on-prem (GigaChat on-prem / T-Pro 2.0 / Qwen3 через OpenAI-совместимый API) — только черновики
                       ├─ правила: сроки 223-ФЗ/381-ФЗ, ст. 395 ГК, пороги АПК — справочник с датами действия
                       └─ заявка в ВТБ Факторинг (по согласию клиента)
```

Масштабирование: обработка счетов — независимые задачи (очередь), Jev и LLM — горизонтально масштабируемые
сервисы инференса; кэш ответов по хэшу текста; тяжёлая часть (LLM) вызывается только для писем,
которые сотрудник открыл, а не для всех счетов. Прототип не рассчитан на промышленную нагрузку.

## Защита данных и регуляторика

| Требование | Как выполняем |
|---|---|
| 152-ФЗ: локализация, запрет первичного сбора ПДн в зарубежные базы (с 01.07.2025), уведомление РКН о трансграничной передаче | только российские / on-prem модели; зарубежные облачные LLM не используются |
| Роли по 152-ФЗ | ВТБ — оператор, команда/сервис — обработчик по поручению; согласие клиента на обработку переписки |
| Минимизация ПДн в моделях | маскирование телефонов, почты, паспорта, СНИЛС перед генеративной моделью (`mask_pii`) |
| Банковская и коммерческая тайна | развёртывание в контуре банка без доступа к открытой сети; журнал доступа |
| Кодекс этики ИИ Банка России (2025, рекомендательный) | метка «Сгенерировано ИИ» на письмах; переключатель «Работать без ИИ»; человек подтверждает каждое письмо, претензию, заявку; модели в реестре моделей банка; экран «Качество ИИ» |
| 115-ФЗ | сервис не проводит платежи; сигналы о контрагентах могут использоваться в процессах «Знай своего клиента» банка |
| ИБ | ролевой доступ, шифрование при хранении, аудит действий, без хранения ключей на клиенте |

Демо на GitHub Pages: данные пользователя остаются в браузере (localStorage), ничего не отправляется наружу.
Живой режим (`server/app.py`) запускается локально.

## Риски

| Риск | Мера |
|---|---|
| Модель ошиблась с причиной → неправильное действие | показываем основание-цитату и вероятности; при неуверенности — шаг «уточнить у клиента»; человек решает |
| LLM придумала сумму/дату в письме | валидатор чисел, предупреждение в интерфейсе, отправка только человеком |
| Нет переписки в системе | работаем по выписке и статусам ЭДО; переписку добавляют пересылкой |
| Клиенту не нужен ещё один инструмент | встраивание в интернет-банк, а не отдельное приложение |
| Конкуренты (Контур, Сбер) добавят ИИ-разбор | скорость, банк-специфичные данные (выписка + факторинг), таксономия причин |
