# Продуктовые метрики

Построено по алгоритму воркшопа «Продуктовые метрики» (Н. Хюнен, 27.10.2026): продукт → клиент → задача →
как продукт решает → как измерить → что влияет → как мы влияем.

| Шаг | Ответ |
|---|---|
| Продукт | Помощник по дебиторке в интернет-банке: причина неоплаты, шаг, письмо, сверка, разрыв, факторинг |
| Клиент | МСБ, оказывающий услуги/поставки B2B с отсрочкой; пользователь — бухгалтер/финменеджер |
| Задача | Быстрее получать деньги за выполненную работу, не тратя время на разбор почты |
| Как решает | Находит причину в переписке, даёт одно действие, готовит письмо, закрывает уже оплаченное по выписке |
| Как измерить | Срок оплаты (DSO), доля счетов, оплаченных к сроку + 7 дней, время от сигнала до действия |
| Что влияет | Точность причины, доверие к рекомендации, скорость действия, полнота данных (почта, ЭДО, выписка) |
| Как влияем | Качество модели, понятное основание (цитата), письмо в один клик, интеграции |

## Дерево метрик

```
North Star: ₽ просроченной дебиторки, возвращённые в срок до +7 дней (по активным клиентам, в месяц)
├── Ценность для клиента
│   ├── DSO (дебиторка / выручка × 30), дни                       — запаздывающая
│   ├── Доля счетов, оплаченных к сроку + 7 дней                    — основной KPI пилота
│   ├── Деньги под риском (остаток × P(не оплатят за 14 дней))       — опережающая
│   └── Время на разбор одного просроченного счёта, мин             — из интервью и логов
├── Вовлечённость
│   ├── Доля просроченных счетов, по которым сделан шаг в течение 2 рабочих дней (time-to-action)
│   ├── Доля принятых рекомендаций (сотрудник выбрал предложенный шаг)
│   ├── Доля отправленных писем без правок / с правками
│   └── WAU / MAU бухгалтеров; доля дней с открытием «Что сделать сегодня»
├── Удержание
│   ├── Retention 4/8/12 недель (компания возвращается с новыми просрочками)
│   └── Доля клиентов, подключивших выписку и почту/ЭДО (глубина интеграции)
├── Монетизация (для банка)
│   ├── Конверсия «разрыв → заявка на факторинг» и объём профинансированных счетов
│   ├── Прирост среднего остатка на расчётном счёте активных клиентов
│   └── Стоимость обслуживания клиента (LLM + Jev), ₽/мес — сейчас ~57 ₽
└── Качество ИИ (защитные метрики)
    ├── Точность / полнота / F1 по каждой причине; отдельно полнота класса «спор»
    ├── Калибровка вероятностей (ECE, Brier)
    ├── Доля писем без фактических ошибок (валидатор) и доля писем, отправленных без правок
    ├── Сверка: invoice-level hit rate, доля автосопоставлений с ошибкой (цель ≤ 1%)
    └── Прогноз: ROC AUC, ECE, медианная ошибка срока (дни)
```

## Типы метрик (по воркшопу)

| Тип | Примеры у нас |
|---|---|
| Опережающие | деньги под риском, time-to-action, доля принятых рекомендаций |
| Запаздывающие | DSO, доля оплат к сроку + 7 дней, объём факторинга |
| Качественные | цитаты из интервью, причины отказа от рекомендации |
| Количественные | всё из дерева выше |
| Высокоуровневые | North Star, DSO |
| Операционные | latency Jev (медиана 1,3 с), стоимость письма, доля ошибок валидатора |

## Текущие значения (демо, синтетика)

| Метрика | Значение | Комментарий |
|---|---|---|
| Jev, причина по письму | 89/89 | синтетика, верхняя оценка |
| Правила, причина по письму | 73/89 (82%) | базовая линия без ИИ |
| Jev, причина по истории счёта | 20/20 | включая трудные случаи |
| Письма без фактических ошибок | 19/20 | 1 выдуманное «до 17:00» поймано |
| Прогноз: AUC / ECE / медиана ошибки | 0,88 / 0,023 / 4,8 дня | синтетика |
| Время ответа Jev | ~1,3 с | медиана 20 запросов |
| Переменная стоимость на клиента | ~57 ₽/мес | 30 писем × 1 ₽ + 90 вызовов Jev × 0,3 ₽ (гипотеза) |

## Цели пилота

| Метрика | Цель | Порог «не работает» |
|---|---|---|
| Доля оплат к сроку + 7 дней (пилот vs контроль) | +8 п.п. | < +2 п.п. |
| Сокращение срока оплаты просроченного счёта | 4 дня | ≤ 1 день |
| Time-to-action ≤ 2 рабочих дня | 70% счетов | < 40% |
| Принятые рекомендации | ≥ 60% | < 40% |
| Macro-F1 причины на реальной переписке | ≥ 0,75 | < 0,6 |
| Ошибки автосверки | ≤ 1% | > 3% |

Статистическая оговорка: в пилоте с сотнями контрагентов заметны только крупные эффекты (от 8–10 п.п.).
Рандомизация — по контрагентам, не по счетам (иначе один клиент получит и тестовое, и контрольное обращение).
